# NavTasks — Stage 3: in-app update preview 0.4.144 RC2

## Intent and architecture
- User approved implementing built-in optional GitHub Releases updates, AFTER Stage2 created public `NavTasks-Updates` with inactive stable.json.
- Separate private feature branch `feature/navtasks-inapp-updates-0.4.144-rc2` forked from Stage2 commit `d3a81382d1cdd6f4521a31cfbba81f8d8233901d`. Preserved previous RC1 source at `backup/navtasks-0.4.142-before-inapp-updates`.
- Candidate stays NON-debuggable signed same-key, same `com.navtasks.app.glass`, versionName `0.4.144-rc2`, versionCode **169** (higher than 0.4.143 recovery/code168).
- Android runtime changes ONLY: a private update controller, strict stable feed parser, popup/settings UI, Manifest INTERNET+ACCESS_NETWORK_STATE+REQUEST_INSTALL_PACKAGES/FileProvider, and minimal Activity/Settings/root integration. No changes to profiles, task recurrence, Handover, AMOS, Services, comments, widgets, reminders, backups or Liquid Glass shaders/dock.
- Stable URL: `https://raw.githubusercontent.com/sergbokarev95-arch/NavTasks-Updates/main/channels/stable.json`. `available:false` is a normal successful result; no user error or modal. Failed automatic checks are silent and do not block startup. Nonblocking coroutine Dispatchers.IO + timeout, 24h successful-check throttle, 5m attempt throttle, and Android ConnectivityManager callback for network return. Manual check in Settings always allowed.
- Strict schemaVersion1, stable only, semantic release name (no RC/beta), `versionCode > installed`, explicit `minSupportedVersionCode <= installed`, OS minSdk, official GitHub release URL, SHA256 and size bounds, signer digest and RU/EN release notes. The app independently checks the downloaded full APK archive applicationId, code, debug flag and actual signing certificate against BOTH the channel metadata AND current installed NavTasks signing cert. The Android system installer verifies the APK cryptographic signature itself.
- Download uses HTTPS with only GitHub-approved redirect hosts, streaming into app-private cache `updates/pending.part` then `updates/pending.apk`, size/hash validation before and after download, progress reporting and cancel/retry. The APK is shared with installer via a FileProvider cache-only content URI. The installer is always the standard Android confirmation UI, never silently installs or bypasses unknown-apps permission. A user can skip a particular offered version ("Позже"), with manual check overriding suppression.
- UI: existing `NavGlassAlertDialog`, existing `NavPanel`, no new dock optics or global colors. Show version/changelog, "Обновить"/"Позже", progress, manual "Проверить обновления" and last success time in Settings.
- First PRERELEASE candidate is private, NOT a stable public release, and public stable feed remains unavailable. No fake test APK published. Pure policy and migration-limits tests run in private Actions, sign/cert/package checks and source frozen hashes via CI.
- **Device acceptance still required:** latest available/no update/offline/network drop/corrupt APK/skipped/cancel system install/unknown-sources policy, HONOR/Samsung support, full installed app data/profile history persistence. When the public stable feed is empty, live download+installer cannot be end-to-end tested without a separately approved test channel.
- Safety: no GitHub token or secrets in APK, no autoplay forced updates, no data-store schema migration in this stage; direct cross-major upgrades remain conditional on separate old-profile compatibility testing. Android allowBackup privacy review still pending.
